## Scope

Phases 0–3 of the plan, plus from phase 4: certifying signatures (DocMDP) and signing empty signature fields. Not in scope: signing password-protected files (refuse, per the plan), Windows, cloud signing, EU trusted lists.

## Ownership

**A: parsing, worker wiring, phase 0.**
- `src/lib/pdfSignatures.ts`: `scanSignatures(bytes: Uint8Array, password?: string): Promise<SignatureScan>` (pdf-lib, run in the worker). Also pure helpers: revision boundaries (`%%EOF` offsets), byte-range checks, `/Contents` gap location. A file with no `/AcroForm` or no `/Sig` fields returns quickly with empty lists.
- Worker wiring for **every** signature job, in `src/lib/pageEditMessages.ts`, `src/lib/pageEdits.ts` (`answerPageEditJob`), and `src/lib/pageEditWorker.ts`: ops `scanSignatures`, `prepareSignature`, `appendDss`, `prepareDocTimestamp`, exported as `scanSignaturesOffThread`, `prepareSignatureOffThread`, `appendDssOffThread`, `prepareDocTimestampOffThread`. The last three call C's functions (signatures below). Extend `PageEditResult` as needed.
- `src/hooks/useDocumentSignatures.ts`: given a tab's current bytes (`pdfDocument.getData()`) and password, runs the scan, then `verifySignatures` (B's platform wrapper), and returns `{ scan, verdicts, loading, error, refresh }`. It re-runs when the tab's `source` changes. It computes nothing cryptographic itself. Unsigned documents cost one worker scan and no IPC.
- Phase 0: before any full rewrite of a document whose scan has signatures, ask once per edit with a native alert ("This document has 2 digital signatures. <Action> removes them." Continue / Cancel). The rewrites are page edits incl. Flatten Form and Set/Change/Remove Password (`src/hooks/usePageEdits.ts`), and the full-rewrite fallback in `writeAnnotations` (`src/lib/notesPdf.ts`). For that one, the worker must report that it had to rewrite, and Save must ask before writing; design it so a refused rewrite leaves the tab edited and nothing written. Owns `usePageEdits.ts` and `notesPdf.ts` for this.
- Tests: `tests/pdfSignatures.test.ts`, with fixtures built in the test using pdf-lib, plus raw byte construction for signed-looking files.

**B: Rust crypto and its TS wrappers.**
- `src-tauri/src/signatures/` (a module: `mod.rs`, plus `verify.rs`, `sign.rs`, `identities.rs`, `trust.rs`, `tsa.rs`, `revocation.rs` as needed), registered in `lib.rs`. B owns `src-tauri/Cargo.toml`/`Cargo.lock` and `lib.rs` changes. All of it is macOS-only behind `cfg(target_os = "macos")`. Other targets return an "unsupported" error so the crate still builds.
- B owns the additions to `src/lib/platform.ts` (only add, don't restructure): `canSignDigitally: boolean`, `verifySignatures(bytes, items: VerifyItem[], dss: DssData | null): Promise<SignatureVerdict[]>`, `listSigningIdentities(): Promise<SigningIdentity[]>`, `signPdf(bytes, request: SignRequest): Promise<Uint8Array | null>` (`null` when the user cancels the confirmation), `fetchValidationData(bytes, items: VerifyItem[]): Promise<ValidationMaterial>`, `timestampPdf(bytes, placeholder, url): Promise<Uint8Array>`, `showCertificate(fingerprintOrDer)`: the native certificate panel. Browser fallbacks: verify returns `unsupported` verdicts, sign/list return nothing.
- IPC: big bytes go as raw request bodies (like `write_pdf`) and come back as `tauri::ipc::Response`. Metadata goes in a percent-encoded JSON `x-request` header. DSS blobs for `verify` go in an envelope body: `u32 LE json length | json | pdf bytes | blobs…`, where the JSON names each blob's offset and length. Rust computes every digest itself from the PDF bytes and byte ranges. It never trusts a hash from the webview.
- Verify: per the plan's phase 1 (CMS parse, `messageDigest`, signature over signed attributes, `SecTrust` with revocation via DSS first then online with a short timeout, judged at the timestamp's time when there's a valid token, `weak` for SHA-1 / RSA < 2048, `level` detection: B-B, B-T when a signature timestamp token is present, B-LT when the DSS covers the chain, B-LTA when a later document timestamp covers the DSS). `/SubFilter /ETSI.RFC3161` items are document timestamps: verify the token over the range.
- Sign (`sign_pdf`): check the placeholder bytes at the given offsets (`<` + `CONTENTS_HEX_LENGTH` `0`s + `>`, and a `[` … `]` of digits and spaces for the byte range), write the `/ByteRange` as `[0 a b c]` padded with spaces before `]` to the same length, hash, show a native confirmation sheet on the calling window ("Sign “<documentName>” as <CN> (<issuer CN>)?" Sign / Cancel), build CMS `SignedData` (detached, signed attributes `contentType`, `messageDigest`, `signingCertificateV2`; no `signingTime`), sign with `SecKeyCreateSignature` on the identity's key (found by certificate SHA-256 fingerprint), add an RFC 3161 token as an unsigned attribute when `timestampUrl` is set, hex-encode into `/Contents` (fail if it doesn't fit), and return the bytes. Run the plan's pre-signing certificate checks again here, since the webview's list isn't authoritative.
- `list_signing_identities`: Keychain identities (including smart cards and tokens), with `usable`, `problems`, and `warnings` per the plan's certificate checks. A live revocation check isn't needed for listing; do it in `sign_pdf`.
- `fetch_validation_data`: for each item, collect the signer chain and timestamp-authority chain from the CMS, fetch OCSP (fall back to CRL) for each non-root certificate, and return DER blobs with VRI entries keyed by the uppercase hex SHA-1 of the signature's `/Contents` bytes (the DER, trailing zero padding removed).
- `timestamp_pdf`: same placeholder fill, then an RFC 3161 token over the range's SHA-256 as `/Contents` (no key and no confirmation).
- Network: TSA and OCSP/CRL over HTTP(S) with timeouts, in Rust only. Nothing else leaves the machine. Use crates already in the tree where possible (check `cargo tree` for `reqwest`, `sha2`, `x509-parser`, and so on); prefer RustCrypto `cms`, `x509-cert`, `der`, `x509-tsp`, `x509-ocsp`, or `cryptographic-message-syntax`, whichever works with an external signer. Test with keys and certificates generated in the tests (`rcgen` or the crates' builders), including a tampered-byte case, an expired certificate, and an untrusted chain. Don't touch the real Keychain in tests.
- Rust files stay under 500 lines each. `cargo clippy -- -D warnings` must pass.

**C: writing signatures into PDFs (TS).**
- `src/lib/pdfSignWrite.ts`, plus `src/lib/signatureAppearance.ts` if it helps:
  - `prepareSignature(bytes: Uint8Array, options: PrepareSignatureOptions): Promise<PreparedSignature>`: one incremental update (never a rewrite; refuse encrypted input with a clear error) that adds or fills the signature field and widget (visible with an appearance stream drawn from `appearance`: the ink outline plus text lines in Helvetica, WinAnsi only; invisible as a zero-size `/Rect`), sets `/AcroForm /SigFlags 3` (creating `/AcroForm` if needed and keeping existing fields), adds the `/Sig` value with `/Filter /Adobe.PPKLite`, `/SubFilter /ETSI.CAdES.detached`, `/M`, optional `/Reason` `/Location` `/Name`, a byte-range placeholder, and `/Contents` of `CONTENTS_HEX_LENGTH` zero hex digits. Certify adds `/Reference` with a DocMDP transform and the catalog's `/Perms /DocMDP`. Refuse certifying when the document already has a signature. `lockField` adds a `/Lock` FieldMDP dictionary (`/Action /Include`, the field itself). The signature dictionary and its placeholder must not land in an object stream. Return exact byte offsets: `byteRangeAt`/`byteRangeLength` span `[` to `]` inclusive, `contentsAt`/`contentsLength` span `<` to `>` inclusive. Refuse documents certified with permission 1, and only allow signing an existing field that has no value.
  - `appendDss(bytes, material: ValidationMaterial): Promise<Uint8Array>`: an incremental update adding or merging the catalog's `/DSS` (`/Certs`, `/OCSPs`, `/CRLs` stream arrays, deduped by content, plus `/VRI` keyed by the given hex names).
  - `prepareDocTimestamp(bytes): Promise<PreparedSignature>`: an incremental update with an invisible signature field whose value is `/Type /DocTimeStamp`, `/SubFilter /ETSI.RFC3161`, and the same placeholders.
  - Every output must open in pdf.js and in pdf-lib, keep every earlier byte identical (assert `output.slice(0, input.length)` equals the input), and leave earlier signatures' byte ranges valid. Look at how `notesPdf.ts` writes incremental updates and edits `/Annots` directly.
- Tests: `tests/pdfSignWrite.test.ts`, including a round trip where the test fills the placeholder with fake CMS bytes the way Rust will, and checks the byte ranges cover everything but the `/Contents` string. If A's scanner exists by then, scan the output with it.
